# 工具治理前端与用户授权概要设计

状态：实施中（2026-09-29）  
范围：管理员工具目录、MCP 工具治理、数字员工绑定、平台用户能力授权  
关联：[工具与 MCP 统一配置及授权边界设计基线](工具与MCP统一配置及授权边界设计基线.md)、[工具与 MCP 实施概要设计](工具MCP实施/工具与MCP实施概要设计.md)、[SPEC-06](工具MCP实施/SPEC-06-工具目录与用户授权.md)

## 1. 背景与目标

当前后端已经具备能力目录、MCP 连接登记/发现/审核、数字员工草稿发布以及运行时工具授权复核；前端已有能力目录、MCP、员工定义和用户管理页面，但缺少用户工具授权界面，能力目录也只显示启停状态。

本次目标是补齐管理员可操作的工具治理闭环：

```text
能力目录查看/启停
       ↓
MCP 连接登记 → 按管理员身份发现 → 逐工具审核批准
       ↓
数字员工草稿选择具体工具修订 → 校验 → 发布
       ↓
平台用户按能力编码授予/撤销使用权
       ↓
Run 创建和每次 Tool 调用继续由服务端按冻结版本、用户授权和工具状态判权
```

## 2. 范围与非目标

### 2.1 本次范围

- 能力目录详情：来源、类型、编码、修订、模型工具名、Schema、业务动作、读写影响、确认规则、实现键（仅管理员可见）和启停状态。
- 用户能力授权查询：按平台 `UserId` 查询能力编码级授权状态。
- 用户能力授权变更：复用已有启用/停用接口，所有变更必须由认证管理员提交原因。
- 管理中心增加独立“工具授权”页签，沿用用户列表和能力目录数据。
- 保留现有 MCP 登记、发现、差异、逐工具批准和员工绑定发布流程。
- 补充后端定向测试、前端构建和文档/验收清单。

### 2.2 非目标

- 不通过管理页面上传或创建任意 Java、脚本、Shell、任意 HTTP、文件或网络执行器。
- 不把 MCP Server 的资源 ACL 复制成平台的平行授权系统。
- 不新增复杂 RBAC、部门/组织授权或资源级 ACL 编辑器；本次仍使用现有能力编码级布尔授权。
- 不接入真实 MCP 用户 Token、真实第三方 Server 或生产数据库升级。
- 不重写 AgentScope 工具循环、MCP 协议客户端和运行时执行网关。

## 3. 对象和职责边界

| 对象 | 本次管理侧职责 | 明确不承担 |
| --- | --- | --- |
| 能力目录 | 展示已登记工具修订、全局启停、详情 | 不在页面生成本地执行实现 |
| MCP 连接 | 登记连接、启停、发现和查看差异 | 不保存终端用户 Token |
| MCP 工具修订 | 逐工具审核，生成可绑定的能力修订 | 不因发现自动批准 |
| 数字员工版本 | 选择具体能力修订并发布不可变版本 | 不等于给所有用户授权 |
| 用户能力授权 | 按平台 UserId 对能力编码授予/撤销 | 不替代 MCP Server 的目标资源判权 |
| Run/Tool Gateway | 使用冻结发布版本并在执行前再次判权 | 不接受前端或模型自报身份 |

本地 Tool 的执行实现仍由运行时白名单提供者和代码注册表承接；数据库与页面只能管理已注册能力的元数据、启停、员工绑定和用户授权。MCP 工具则必须经过连接登记、受控发现和逐项批准后，才能出现在能力目录与员工草稿中。

## 4. API 设计

### 4.1 已有接口复用

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/admin/v1/capabilities` | 查询工具能力目录及契约详情 |
| PUT | `/api/admin/v1/capabilities/{capabilityCode}/status` | 全局启停能力 |
| PUT | `/api/admin/v1/users/{userId}/capability-grants/{capabilityCode}` | 授予/撤销用户能力 |
| GET/POST/PUT | `/api/admin/v1/mcp/connections...` | MCP 连接、发现、差异和批准 |
| GET/PUT/POST | `/api/admin/v1/agents/{employeeId}...` | 员工草稿、校验与发布 |

### 4.2 本次新增接口

```http
GET /api/admin/v1/users/{userId}/capability-grants
```

响应：

```json
[
  {"userId": 1001, "capabilityCode": "meeting_room.search", "enabled": true},
  {"userId": 1001, "capabilityCode": "meeting_room.reserve", "enabled": false}
]
```

约定：

- 只返回该用户已有的授权记录；没有记录表示默认未授权，前端与能力目录按编码合并展示。
- 查询不写审计；变更继续使用现有事务和 `USER_CAPABILITY_GRANT_CHANGED` 审计事件。
- 管理员身份由安全上下文确定，不能从路径或请求体伪造操作者。
- 该接口表达平台能力编码级授权，不表达 MCP 目标资源 ACL。

## 5. 前端交互

### 5.1 能力目录

- 保留搜索、启停和操作原因输入。
- 每行增加“详情”入口，以抽屉/对话框展示 Schema、来源和运行约束。
- `implementationKey` 只对管理员展示，用于诊断提供者是否已部署，不下发给普通用户和模型。
- 对 MCP 能力显示连接来源和“由 MCP Server 最终判权”的提示。

### 5.2 工具授权

- 管理员选择一个用户，页面加载能力目录和该用户已有授权。
- 以能力编码为粒度展示授权开关；同一编码的不同修订共享授权状态。
- 能力全局停用时显示停用状态，禁止误认为用户授权即可调用。
- 每次切换都要求填写操作原因；提交失败时恢复服务端原状态并提示。
- 用户列表使用现有脱敏手机号和用户状态，不展示激活凭据。

### 5.3 MCP 与员工发布

现有 `McpPanel` 和 `DefinitionPanel` 保持主流程不变，只补充来源、修订、确认策略和授权边界提示。发现候选不能直接绑定员工；只有批准的能力修订才能在员工草稿中选择。

## 6. 数据流与安全约束

1. 页面通过 Cookie/WebSession 访问管理员 API。
2. Controller 读取认证主体，调用 platform service；不接受客户端 actor 字段。
3. Service 校验能力编码存在，调用 repository 读取/写入。
4. JDBC repository 查询 `agent_user_capability_grant`；写入继续在事务中追加管理审计。
5. Run 创建和 Tool Gateway 仍按已发布版本、当前能力状态、用户授权和目标资源策略再次判权。
6. 能力停用或用户撤权只阻止尚未越过执行检查的调用；不能宣称已经发出的外部副作用被回滚。

## 7. 验收标准

- 管理员可以查看每项工具的契约详情并启停能力。
- 管理员可以按用户查看、授予和撤销能力授权，且每次变更需要原因。
- 匿名或非管理员访问管理接口被拒绝；请求体不能改变审计操作者。
- 用户授权和能力停用状态在后端查询中可读回，并能影响后续运行时判权。
- MCP 登记、发现、审核、员工绑定和发布流程不回归。
- 不泄露 Token、激活凭据、原始手机号、隐藏能力名称或 MCP 内部消息。
- 真实 MCP 凭证、真实第三方 Server、生产数据库和跨进程恢复仍标为未验证。
