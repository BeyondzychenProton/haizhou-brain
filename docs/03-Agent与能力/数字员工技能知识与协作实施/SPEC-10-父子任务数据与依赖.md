# SPEC-10 父子任务数据与依赖

状态：V31 父子工作项持久化、输入修订与精确依赖引用、结果绑定/显式验收以及必需项根完成阻断已实现；仓储回归与 V1–V31 Testcontainers MySQL 迁移验证通过。完整 P1/P2 并行合成、复核、修订到根交付的端到端编排，以及取消/晚到/写入不确定故障注入尚未验收，因此本 SPEC 仍是新协作 profile 的发布阻断项。任务：C15、C16。依赖：[03](SPEC-03-完整结果与原子交付.md)、[09](SPEC-09-只读专家调用与预算.md)。设计依据：[详细设计](../数字员工技能知识与只读协作改造详细设计.md) §3.6、§5.6、§8.8、§9.4、§12、§13.6。

## 对象与原生映射

Session 是产品会话，Run 是根执行；workItem 是业务资料/验收对象，delegation 是子实例关联，invocation 是某一轮调用。原生 taskId/agent_key/toolUseId 都分别保留，不能互相顶替。任务执行/认领复用原生仓储和 Team 任务板，平台不建工作项派发 Worker。

## 输入与有效规格

- 根建立 workItemRef 和不可变输入修订：目标、交付契约、required、授权资料引用/哈希、依赖、检查策略、固定/来源角色、剩余预算与截止时间。
- effectiveChildSpec 冻结父允许能力与子配置的交集；子不得扩大权限、换模型/版本或修改父截止时间。
- 把结构化契约编码为原生 spawn/send 的受控任务内容，关联到服务端 Scope；文本不是可信身份或权限声明。
- 复核对象显式指定 resultId/contentHash/contractVersion；不读取 latest。依赖未成功/错版在受理边界拒绝，不创建平台等待队列。
- 同 workItem/输入修订的幂等及预算占位同事务；记录实际原生接受/启动证据，不把输入提交等同未启动。

## 输出与检查

- 子实际最终消息完整保存为 TEXT/JSON 等批准契约，带产物/资料引用、哈希、限制与检查结果；原生正常结束不等于资料合格。
- 原生 spawn 回复可能含前缀/封装；以实际最终消息与批准映射读取，不将任意回复字符串冒充结构化正文。
- 平台格式/引用检查与原生任务 completed/failed 分开记录。根决定验收/修订/部分交付，ROOT_FINAL 独立保存。
- 必需失败阻止其依赖下游；允许部分交付也需明确列出缺失与已接受范围，不自动变全部成功。
- 结果已保存但父消费不明进入 SPEC-04 核查；平台补投影不重新执行已完成子任务。

## 验收

覆盖详细设计 §8.8.6 完整案例：P1/P2 并行 → 合成 → 复核精确版本 → 修订 → 根交付。检查 TEXT/JSON、缺必需项、非法/越权引用、哈希错版、重复修订、依赖未就绪及部分失败。

故障注入输入提交后未明启动、原生完成后结果写失败、根消费不明、取消后晚到。正确结果为幂等补事实或 RECOVERY_REQUIRED，不能靠重跑模型掩盖不确定状态。
