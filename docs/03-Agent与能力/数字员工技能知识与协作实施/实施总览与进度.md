| 技能、计划、文件 | 冻结技能中间件、原生 Plan 工具、RemoteFilesystemSpec、JdbcStore | 审核资产、不可变发布、完整性校验、SESSION 命名空间和只读约束 |
| 子 Agent | agent_spawn、agent_send、subagentFactory、原生管理器 | 受信角色/实例映射、只读构建、业务预算、输入输出快照 |

不新建第二套推理循环、计划管理器、任务派发队列或成员消息总线。平台记录工作项与调用的资料、权限和结果关联；原生任务板仍是自治 Team 的任务状态事实源。

## 3. 贯穿所有 SPEC 的约束

- 一个 Session 只有一个业务根 Run 的排队/取消所有者；原生成员 gate 只保护各成员内部执行。
- ROOT/CHILD 相对当前业务 Run 判定；用户直接选择专家时该专家是 ROOT。角色名不能代替归属证据。
- Run 事件与 Session 投影在同一平台事务提交；AgentState/KV 与平台数据库事务分开，不承诺跨两者 exactly-once。
- 固定版本、资产与执行规格由服务端生成，外部字段、模型文本不能授予身份或权限。
- 子 Agent 不扩大父 Run 权限。INTERNAL、思考链和敏感原始参数不进入用户流或渠道。
- 新 profile 状态不确定时 RECOVERY_REQUIRED 占槽，不因租约过期自动并发接管。旧 profile 按兼容契约回归。
- 未来群聊仅保留 conversation/task、参与者/执行归属、可见性和可信身份的扩展边界；本轮无群聊模式、成员增删接口或群触发实现。
- 只新增 Flyway 迁移；当前 V13–V19 及旧发布包、旧物理状态键保留。迁移编号按实施时仓库最高版本分配。
