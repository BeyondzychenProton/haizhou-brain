# SPEC-05 技能知识资产管理

状态：管理服务、资产版本/文件持久化、API 与结构化校验已实现并通过定向测试；V22 迁移随 V1–V33 全量迁移及后端全量回归通过。管理页面人工审核流程尚未做浏览器验收。任务：B1。依赖：SPEC-01–04 的可靠性门槛。设计依据：[详细设计](../数字员工技能与只读协作改造详细设计.md) §4、§14、§16。

## 目标与边界

复用 capability 的 SKILL/KNOWLEDGE 分类，增加经过管理员校验发布的不可变文本资产修订。框架只负责消费技能；平台负责审核、归属与版本。首期不做向量检索、私有用户知识自动采集或多级审批。

## 数据/API 契约

- 资产草稿带 expectedDraftRevision，保存规范文件列表和 reason；发布 requestId 幂等，冻结 capabilityRevisionId/manifestHash。
- 每个文件包含规范相对路径、UTF-8 文本、字节长度和服务端内容哈希；manifest 包含媒体类型、数量和总量。
- SKILL 验证 SKILL.md/声明格式；KNOWLEDGE 提供只读入口/索引。不能把脚本自动变成可执行工具。
- 新增草稿/修订/文件持久表及必要唯一键；修订发布后不可改，旧修订引用仍可审计。
- 管理 API 沿用 `/api/admin/v1/capabilities`，新增 `/capability-assets/{capabilityCode}/draft`、`/publish`、`/revisions/{revisionId}`，完整路径按详细设计 §14。
- 管理员身份从认证获得；审核状态/hash 由服务端产生。正文预览经安全渲染，不接受主机任意文件路径。

## 文件校验与实施

拒绝绝对路径、盘符/UNC、`..`、大小写碰撞、保留入口冲突、symlink/reparse escape、编码与大小超限。按 Windows 最终规范路径和 UTF-8 字节数校验；业务发布目录不包含 Token/真实私人资料。

沿用 platform 能力管理与审计入口，infrastructure 新增仓储/迁移，api 扩展结构化校验问题。保存草稿与发布修订分别事务化，避免发布失败产生可引用半成品。

## 验收

1. 正常创建技能/知识 → 校验 → 发布 → 查询同一不可变内容，重复 requestId 得到相同修订。
2. 草稿修订冲突 409；新修订不改变旧员工发布包引用的资产。
3. 穿越、大小写冲突、非法入口、超限等输入被拒，落库/物化均不发生越界文件写入。
4. 跨租户/非管理员/未审核资产拒绝；错误定位到文件 fieldPath。
5. 新迁移在真实 MySQL 验证唯一键、长文本和回滚；资产 UI 随 SPEC-14 接入。
