# SPEC-11 通用及动态专家

状态：通用与动态专家工厂已接入原生 Harness 中间件；动态路径通过确定性模型探针验证了同一 Run 内 `agent_generate` 生成、原生注册并由 `agent_spawn` 执行。只读子 Agent 继承可信用户和 Run fence，且模型工具表为空。真实模型、通用专家实际执行、并行实例隔离、重启后定义读取及拒绝路径矩阵尚未验收；本 SPEC 与动态 profile 仍保持关闭。任务：C14。依赖：SPEC-00 动态/并行契约、09、10。设计依据：[详细设计](../数字员工技能知识与只读协作改造详细设计.md) §8.6、§9、§13.6。

## 原生复用

验证并复用原生 general-purpose factory；运行时定义复用 agent_generate、SubagentSpecGenerator、DynamicSubagentsMiddleware 与原生注册。固定角色仍走已发布版本。动态生成不等于给自治 Team 动态部署成员。

## 安全与生命周期

- general-purpose 同实例 active 1；同类型并行必须有 agent_key/childSession/toolUseId/source 独立映射证据，未证明时不开放。
- 动态角色使用 dyn- 名称空间，不允许覆盖固定角色/通用名称；限制数量、定义长度、步骤、工具和文件来源。
- 生成声明审核归一为 Session scoped 的只读有效规格，绑定创建来源/父版本/hash；不将模型声明直接视为批准策略。
- 原生默认生成路径的 middleware 必须显式接线并验证 leaf 工具集，不能只启用 agent_generate 就声称可执行安全专家。
- 动态定义可作为当前 Session 获准资料保留；活实例是父 Run 生命周期资源。恢复不复活未知 agent_key；普通用户不能直接续聊/暴露已生成子实例。
- 标注生成/通用来源与实际 executor，没有正式 employee/version 时保留空值，不伪造员工发布记录。

## 实施步骤

先探针确认默认 factory 的公开可控构建点与同名注册行为，再薄适配只读约束。预算、输入输出、事件与结果全部复用 SPEC-09/10；不新增一套“动态专家执行链”。

## 验收

1. 通用同实例跟进与两实例并行互不串上下文、工具、文件或来源；取消其中一个不会取消另一个。
2. 生成专家从定义到原生注册/执行/结果真实跑通，所有 child 的安全工具断言与固定角色相同。
3. 覆盖静态名字、越权工具、超限定义、跨 Session/Run key、后台/expose 等尝试被拒。
4. 重启能读取定义/结果，但不伪称自动恢复原活实例；不确定消费仍保护性核查。
5. 独立开关和验证门槛；固定只读角色可用不自动开放动态角色。
