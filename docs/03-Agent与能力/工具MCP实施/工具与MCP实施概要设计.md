# 工具与 MCP 实施概要设计

状态：实施中（2026-09-28）。本设计承接[统一配置与授权边界基线](../工具与MCP统一配置及授权边界设计基线.md)，不得将模拟环境视为生产身份对接已完成。

## 目标与边界

本地 Tool 与可信 MCP 子工具共用能力目录、员工草稿/发布和 Run 工具视图。平台负责连接及逐工具批准、发布版本、逐用户发现、Run 冻结、确认、路由和审计。MCP Server 根据终端用户身份逐次判定目标资源；本地 Tool 保留平台 Resource + Action 判权。AgentScope 2.0.3 承担 Harness、Schema 和 MCP 客户端协议能力；平台不复制 MCP 的业务 ACL。

```
管理员：连接登记 → 按用户发现 → 逐工具批准 → 员工绑定 → 发布不可变能力包
用户：认证身份 → 逐用户 tools/list → 创建 Run 并冻结可见集合 → 模型提出调用
执行：核对 Run/修订/启停/确认 → 本地平台判权 或 MCP 用户身份逐次判权 → 持久结果
```

模拟 MCP Server 是本次验收设施：测试手机号对应的主体经 HMAC-SHA256 签名、带过期时间和受众的 Token 传递。它不代表生产凭证取得、续期或真实 MCP Server 的信任验收。

## 模块分工

| 模块 | 责任 |
| --- | --- |
| `platform` | 连接/工具契约、发现批准服务、Run 列表投影、执行策略分支；不依赖 Spring 或 MCP SDK |
| `infrastructure` | MySQL 持久化、AgentScope 2.0.3 锁定版本的 MCP Java SDK 客户端薄适配、模拟凭证解析 |
| `api` / `bootstrap` | 管理接口、安全装配、功能开关和依赖接线 |
| `web` | 连接、候选、批准、启停、员工绑定的管理界面及错误提示 |
| `test-support` | 可独立启动的可信模拟 MCP Server，双用户隔离与资源判权 |

先交付只读纵向切片，再交付具有幂等/核查的写操作。远端新增或漂移不得自动发布；旧 Run 只收窄。模拟器限本机/测试环境。接口、状态和测试详见[详细设计](工具与MCP实施详细设计.md)及本目录 SPEC。
