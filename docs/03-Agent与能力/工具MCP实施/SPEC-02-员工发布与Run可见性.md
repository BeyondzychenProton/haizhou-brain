# SPEC-02 员工发布与 Run 可见性

状态：实施中。依赖[详细设计](工具与MCP实施详细设计.md)。

连接停用及再启用都递增配置修订，旧工具来源映射永久失配；重新启用须重新发现、批准新工具修订并重新发布员工，旧 Run 不能因状态切回而重新获得工具。

员工草稿只绑定 `TOOL` 或已批准的 `MCP` 子工具修订；发布时编译不可变 Schema 包并记录来源。发布预览和校验列出连接、远端名、影响与确认。新 Run 的模型工具名为发布包、当前启用工具及当前用户 `tools/list` 的交集；本地 Tool 继续查平台用户 Grant。仅当 Run 包含 MCP 工具时作逐用户预检；预检异常使 Run 创建失败，不将失败解释成零工具。旧 Run 不因新增工具或新授权扩张；调用时再查当前停用与 Server 最终授权。

验收：本地 Tool 行为不回归；用户 A/B 的 Run 视图不同；同一用户新授权仅影响新 Run；撤权阻断旧 Run 尚未发送的调用；发布版不因远端目录新增自动变化。

本轮落地：员工可选择 MCP 能力并发布；Run 创建按终端用户 `tools/list` 和已审核输入/输出 Schema 冻结视图，旧 Run 调用再校验。管理页已显示拟发布工具名、来源类型、动作与确认要求；连接/远端名以及新旧版本差异的完整预览仍待补，不能把这张契约表视为完整的发布差异预览。
