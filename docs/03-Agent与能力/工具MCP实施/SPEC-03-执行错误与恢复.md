# SPEC-03 执行、错误与恢复

状态：实施中。依赖[详细设计](工具与MCP实施详细设计.md)。

MCP 执行仍从持久 `PlatformToolExecution` 进入，按 `RunId/toolUseId/capabilityRevisionId` 对照发布包与冻结视图，确认并核对用户激活、连接/工具启停。准备与发送前均复核撤权；调用前重新读取终端用户 `tools/list`，核对名称和已批准 Schema。仅本地 Tool 执行平台业务 ACL；MCP 使用 Run 属主的临时凭证逐次调用 Server。远端工具名、连接 ID 来自已批准映射，不取模型参数。

错误至少分类认证失效、资源无权限、调用前不可用、业务错误、写结果未知；敏感原始报文和 Token 不进入普通审计。只有 Server 明确声明 `NOT_EXECUTED` 的拒绝才确定可判为无权限；SDK 未可靠传递状态的写请求归结果未知。写调用发送后超时或通信断开须落 `RECONCILIATION_REQUIRED`，不盲重试。验收：401/403、伪造用户、同名工具、停用、Schema 漂移、写后超时、幂等重放和结果核查。

本轮落地：模拟 Server 的认证和授权错误契约、确认门槛、响应丢失的待核查结果及查询路径已测。凭证取得在任何远端请求前失败时，执行结果为 `CREDENTIAL_UNAVAILABLE`，不误归类为未知写结果；写请求发出后结果不明仍须待核查，这两类路径均有网关级测试。真实 Server 的错误格式、写副作用与重启恢复仍需对接验收。客户端不自动重试未知写结果。
