# SPEC-01 连接、发现与批准

状态：实施中。依赖[详细设计](工具与MCP实施详细设计.md)。

连接由管理员登记编码、显示名、Streamable HTTP URL、启停和变更原因。URL 准入必须拒绝不受信任目标；测试模拟器仅在显式测试配置下接受本机。发现使用指定终端用户身份返回候选快照；列表失败不写入空快照。仅可批准当前快照中的单个子工具，要求审核说明、读写影响、确认和 Schema；批准生成不可变能力修订及来源映射。新候选不自动成为员工能力；旧修订不可原地更新。

API 提供连接列表/登记/启停、发现候选/差异、逐工具批准；输入校验、管理员认证和原因审计必备。验收：跨连接同名冲突、分页、Schema 漂移、停用、发现失败、用户隔离。

持久候选差异读取同一连接、同一管理员最近两次成功保存的发现快照（按快照 ID 倒序），展示各自时间、连接修订，以及按远端工具名比较的新增、消失、说明/Input Schema/Output Schema/只读提示变化。未满两次发现时只展示已有快照信息，不推断新增。历史差异是只读管理信息；批准必须引用该管理员在该连接下仍属最新、且连接修订仍有效的快照，后端在批准事务内再次核对，以防展示后发生新的发现。快照不跨管理员合并；停用后的历史差异仍可查看，批准仍受启用状态限制。数据沿用 V17 的发现快照表，不新增迁移。验收覆盖用户隔离、重启后读取、字段漂移、旧快照拒绝批准、连接停用和修订变化。

本轮落地：登记/启停、按管理员身份分页发现、逐工具批准及原因审计已实现；模型工具名由 V18 唯一占用表防止跨连接并发碰撞。页面以“发现工具”兼作连接探测，独立健康检测尚未交付。持久差异视图与最新快照批准约束已由[增量验收报告](../../07-测试报告/MCP持久发现差异视图验收报告.md)中的 MySQL 集成测试验证。
