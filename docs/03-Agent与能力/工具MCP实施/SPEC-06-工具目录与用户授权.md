## 2. API 验收契约

### GET 用户能力授权

- 正常：`200`，返回 `[{userId, capabilityCode, enabled}]`。
- 无记录：`200 []`。
- 未登录：`401`。
- 非 `PLATFORM_ADMIN`：`403`。
- 非法用户 ID：按现有错误处理返回 `400` 或领域错误，不泄露其他用户数据。

### PUT 用户能力授权

- 保持现有路径和请求体：`{"enabled": true|false, "reason": "..."}`。
- 空原因、超过 500 字或未知能力必须被服务端拒绝。
- 审计操作者取认证主体，不取请求体中的用户字段。

## 3. 前端验收场景

| 场景 | 操作 | 期望 |
| --- | --- | --- |
| 目录详情 | 打开能力目录的详情 | 可看到 Schema、来源、修订、动作和确认规则 |
| 用户选择 | 打开工具授权页并选择用户 | 显示该用户的授权状态，未记录能力默认为未授权 |
| 授予 | 打开未授权开关并填写原因 | 请求成功，开关更新，出现成功提示 |
| 撤销 | 关闭已授权开关并填写原因 | 请求成功，刷新后仍为未授权 |
| 拒绝 | 不填原因或服务端返回 403 | 不提交/恢复原状态并显示错误 |
| 停用 | 能力已全局停用 | 页面显示停用，不能误导为可用 |
| MCP | 打开 MCP 工具详情 | 显示“连接已审核但业务资源由 MCP Server 最终判权” |
