## 目录组织

```text
docs/
├── 文档索引.md                         # 文档索引与管理约定
├── guides/
│   ├── 智能体框架能力参考.md             # 框架能力与项目映射
│   ├── 智能体框架接入验证清单.md         # 源码阅读与验证清单
│   └── 智能体框架学习路线.md             # 面向本项目的学习路线
└── design/
    └── agent-platform/
        ├── 设计文档总览.md             # 当前设计入口和专题顺序
        ├── 会议室预定首个业务闭环详细设计.md # 首条 Mock 预定链路
        ├── 功能地图与框架骨架.md       # 产品功能和模块骨架
        ├── 平台概要设计.md               # Agent 平台概要设计
        ├── 请求执行链路与控制.md         # 请求执行链路与控制概要
        ├── 平台整体工程架构.md           # 整体工程架构草案
        ├── 数字员工多渠道接入与消息流转设计.md # 多渠道接入与消息流转
        ├── 用户身份与跨系统Token设计.md # 用户、平台登录与外部凭证
        ├── Agent能力配置与发布架构.md       # 能力目录、发布与运行时装配
        ├── Agent资源与动作权限设计.md       # 资源、动作与确认规则
        └── 历史设计文档核对与迁移说明.md     # 历史方案与当前方案对照
```

- 设计文档按业务主题归档到 `design/<topic>/`，同一主题的概要与后续详细设计放在一起。
- `平台概要设计.md` 是该主题的概要入口；详细设计按内容命名，例如 `会话运行设计.md`。仅在有实际内容时创建。
- 后续操作指南放入 `guides/`；需要单独留存的重大架构决策放入 `decisions/`。目前不创建空目录。
- 文档文件名使用简洁的中文主题名；目录沿用现有结构，正文保留必要的技术术语。

## 维护约定

1. 新增、移动文档时同步更新本索引，仓库根《项目说明》保留文档入口。
2. 设计文档标明状态、版本、更新日期、适用范围；区分已确定原则、后续细化项和实现状态。
3. 同一主题持续维护固定文件，不使用“最终版”“最终版2”等重复文件；历史由 Git 管理。
4. 变更已确认的设计原则时，在原文中更新结论并记录变更摘要，避免新旧结论并存。
5. 仓库内链接使用相对路径；外部参考使用原始项目或官方文档链接。外部实现不自动构成本项目的能力承诺。
