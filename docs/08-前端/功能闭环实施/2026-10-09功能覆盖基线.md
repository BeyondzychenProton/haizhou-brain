# 后端功能与前端覆盖盘点

日期：2026-10-09（北京时间）
仓库：海卓智慧大脑
分支：`refactor/session-runtime-identity`
基线提交：`eda9c79bd438df9f84f4b2c86c320dc8a0f078ba`
范围：全部后端功能，覆盖普通用户页面和管理后台。
验证层级：当前源码、API、配置、迁移、原生框架接入和相关文档的静态核对。本轮没有启动服务、运行单元/集成测试或做浏览器业务验收。

## 盘点结论

当前前端已覆盖基础工作链路：登录、数字员工、会话、实时输出、排队、取消、引导、工具确认，以及能力目录、工具授权、MCP、员工基础定义和用户管理。技能与知识资产管理已嵌入“能力目录”。

主要缺口集中在账号激活、完整回答校准、员工运行配置与专家编排、渠道管理、异常运行处置，以及结果反馈和已发布资产查看。工作项、审计和渠道投递已经有部分持久事实，但查询接口和安全展示模型也需要补齐。

最值得优先处理的是长回答：后端完整正文已保存，持久事件正文最多保存 4,000 字符；页面未调用完整结果接口，并用完成事件替换流式文本。静态链路显示长回答存在展示被裁剪的风险；本轮尚未做浏览器复现。

本次清单不以“有接口/有类/有迁移”直接等同生产可用。员工新的技能/团队运行方式默认仍关闭，真实 MCP 身份与 IM 提供方适配没有被本轮验证为可用。

## 判定口径

| 分类 | 含义 | 后续工作 |
| --- | --- | --- |
| A：接口已有，界面缺失 | 后端当前有对应 HTTP 行为，前端没有入口 | 对接接口、补页面、验收失败路径 |
| B：页面已有，覆盖不完整 | 前端有页面/封装，但漏了后端字段或操作 | 补现有页面和完整数据流 |
| C：只有内部事实/端口，管理契约不足 | 存储或运行逻辑已实现，但缺查询、权限过滤、分页等 | 后端查询与前端一起完成 |
| D：契约、骨架、未开放或未接入 | 类型、扩展点或受控实现存在，业务可用性不成立 | 先完成后端/验收，不能仅补按钮 |

P1 表示建议先补、影响当前功能闭环；P2 表示随后补齐操作体验与管理可见性。优先级是本次盘点建议，不是已经授权实施的范围。

## A 类：已有接口，明确缺少前端入口

### A1. 新用户激活（P1）

后端有 `POST /api/v1/auth/activate`，接收一次性激活凭据和新密码。管理员已能创建账号、重发并复制激活凭据；用户登录页没有激活入口，路由和 auth API 封装也没有激活操作。

建议增加激活页面，提供凭据、新密码、确认密码、过期/失效提示与激活后的登录入口。密码初次设置与管理员创建账号应成为同一条可用产品流程。

证据：[AuthController.java](<../../../haizhuo-brain-api/src/main/java/com/haizhuo/brain/api/auth/AuthController.java#L59>)、[auth.ts](<../../../haizhuo-brain-web/src/api/auth.ts#L1>)、[UserPanel.vue](<../../../haizhuo-brain-web/src/views/admin/UserPanel.vue#L89>)、[index.ts](<../../../haizhuo-brain-web/src/router/index.ts#L3>)。

### A2. 已登录用户日常修改密码（P2）

后端改密接口已有，前端也有表单，但当前路由规则会将“不需要强制改密”的用户从改密页重定向回员工页。侧栏仅有退出登录。

建议在个人账号菜单提供“修改密码”，让普通改密与强制初始改密分别体现各自的导航规则。无需另造身份服务。

证据：[index.ts](<../../../haizhuo-brain-web/src/router/index.ts#L3>)、[AppLayout.vue](<../../../haizhuo-brain-web/src/layouts/AppLayout.vue#L1>)、[PasswordChangeView.vue](<../../../haizhuo-brain-web/src/views/auth/PasswordChangeView.vue#L1>)。

### A3. 渠道账号、身份绑定与运行状态（P1）

后端已有 8 个管理 API，包含：

1. 查询/创建渠道账号，查询单个账号。
2. 启停、修改默认数字员工和会话隔离方式。
3. 外部用户身份列表、绑定到平台用户、撤销绑定。
4. 查询 Channel 运行时装载状态。

前端无对应菜单、页面或 API 封装。建议增加“渠道管理”，在一页中呈现账号配置、身份绑定和装载状态；凭据只处理引用，沿用后台现有规则。

这页可对接已实现管理 API，但不能因此宣称企业微信、飞书等真实渠道已上线：现有入站是统一 HMAC 模拟协议，出站默认只有模拟发送器。真实渠道仍需提供方验签/载荷/发送适配与验收。

证据：[ChannelAdminController.java](<../../../haizhuo-brain-api/src/main/java/com/haizhuo/brain/api/channel/ChannelAdminController.java#L54>)、[ChannelAdministrationService.java](<../../../haizhuo-brain-platform/src/main/java/com/haizhuo/brain/platform/channel/ChannelAdministrationService.java#L61>)、[ChannelWebhookController.java](<../../../haizhuo-brain-api/src/main/java/com/haizhuo/brain/api/channel/ChannelWebhookController.java#L43>)、[ChannelConfiguration.java](<../../../haizhuo-brain-bootstrap/src/main/java/com/haizhuo/brain/bootstrap/configuration/ChannelConfiguration.java#L101>)。

### A4. 异常运行的管理员核查与终止（P1，需查询补齐）

用户页面已能显示 `RECOVERY_REQUIRED` 并阻止下一轮；后端有管理员显式终止接口，要求当前 fence、请求幂等键、停止证据引用和原因，并写入审计。

管理员没有待核查列表、详情或操作入口。现有普通 Run 响应也不提供处置所需的 fence 和执行核查信息。因此不能只新增一个终止按钮：应先补管理员受保护查询，再做核查和终止流程。不要把该接口呈现为普通“重试”或无需证据的“恢复”。

证据：[SessionView.vue](<../../../haizhuo-brain-web/src/views/app/SessionView.vue#L86>)、[RunRecoveryAdministrationController.java](<../../../haizhuo-brain-api/src/main/java/com/haizhuo/brain/api/admin/RunRecoveryAdministrationController.java#L35>)、[JdbcRunRecoveryStore.java](<../../../haizhuo-brain-infrastructure/src/main/java/com/haizhuo/brain/infrastructure/run/JdbcRunRecoveryStore.java#L31>)、[SessionController.java](<../../../haizhuo-brain-api/src/main/java/com/haizhuo/brain/api/session/SessionController.java#L209>)。

### A5. 回答反馈与运行评分（P2）

后端已有受保护评分接口，接收 0~1 数值及可选意见，绑定当前用户的 Run 后进入 Langfuse 异步队列。页面没有好评/差评、评分或意见入口。

建议在已完成回答旁接入轻量反馈；交互应正确处理观测未启用和入队失败。响应 `accepted=true` 仅代表本地队列接收，不代表远端评分已持久化；若要查询评分历史，需要增加对应读路径。

证据：[RunEvaluationController.java](<../../../haizhuo-brain-api/src/main/java/com/haizhuo/brain/api/session/RunEvaluationController.java#L44>)、[LangfuseEvaluationService.java](<../../../haizhuo-brain-observability/src/main/java/com/haizhuo/brain/observability/LangfuseEvaluationService.java#L20>)。

### A6. 已发布技能/知识修订查看（P2）

后端可以按能力编码及修订 ID 读取已发布正文。资产列表返回当前已发布修订 ID，但现有界面只显示修订号/哈希，操作入口只打开草稿。

建议先增加“查看当前已发布版本”，对接现有接口；“全部修订历史、版本比较”还需要增加修订列表查询，不应把按 ID 读取当成完整版本管理。

## B 类：已有界面但没有覆盖后端完整能力

### B1. 员工运行配置、固定专家与预算（P1，保留发布开关）

草稿 API 与前端类型已支持 `configuration`：员工运行方式、最大迭代、并行委派、专家调用预算、同步超时、固定成员与版本、可选角色及委派关系。

当前 DefinitionPanel 只编辑系统指令、模型供应商/名称和能力绑定；加载草稿时忽略 configuration，保存时也不提交。后端会保留原配置，因此不是“保存时清空 Team 配置”，实际问题是“管理员无法查看或修改这些配置”。

建议沿用员工定义页增加运行配置区和成员/版本选择，并将校验的 fieldPath 定位到表单。现有发布版本读取主要用于平台内部，前端成员选择需要补版本查询契约。

局部差异也需同步处理：

- 前端对所有草稿都要求至少一项能力，后端仅 LEGACY_STABLE 必须如此，新配置可以零工具。
- 前端系统指令限制 4,000 字符，服务层支持到 12,000。
- 当前默认启用列表只有 LEGACY_STABLE，新运行方式未通过既定验收时应呈现为不可发布。

员工的“运行配置 profile”与每次提交的“Run mode”是两个概念。当前 Session 服务只允许 DIRECT；COLLABORATIVE/AUTONOMOUS 只是枚举，直接提交会被拒绝，不能把缺模式按钮误列为纯前端缺口。

证据：[EmployeeRuntimeConfiguration.java](<../../../haizhuo-brain-platform/src/main/java/com/haizhuo/brain/platform/employee/EmployeeRuntimeConfiguration.java#L9>)、[admin.ts](<../../../haizhuo-brain-web/src/api/admin.ts#L150>)、[DefinitionPanel.vue](<../../../haizhuo-brain-web/src/views/admin/DefinitionPanel.vue#L121>)、[AgentDefinitionManagementService.java](<../../../haizhuo-brain-platform/src/main/java/com/haizhuo/brain/platform/employee/AgentDefinitionManagementService.java#L61>)、[AgentCapabilityConfiguration.java](<../../../haizhuo-brain-bootstrap/src/main/java/com/haizhuo/brain/bootstrap/configuration/AgentCapabilityConfiguration.java#L28>)、[SessionApplicationService.java](<../../../haizhuo-brain-platform/src/main/java/com/haizhuo/brain/platform/session/SessionApplicationService.java#L99>)。

### B2. 工具授权的用户范围与撤权（P2）

已有授权读取和写入页，不能沿用旧审计把它判作完全缺失。当前存在两个静态可确认的操作限制：

- 用户选择器一次只取前 100 个 ACTIVE 用户，没有服务端搜索或翻页；更多用户可能无法被选中。
- 全局停用能力时授权开关被禁用，管理员无法通过该页撤销已经存在的用户授权。能力停用会阻止执行，但历史授权管理仍应可控。

建议接入远程用户查询/分页，区分“授予被停用能力”与“撤销已有授权”的限制。资源级权限当前主要依赖远端 MCP；本地 DefaultToolResourcePolicy 的细粒度实现仍是后端缺口。

证据：[ToolGrantPanel.vue](<../../../haizhuo-brain-web/src/views/admin/ToolGrantPanel.vue#L48>)、[ToolGrantPanel.vue](<../../../haizhuo-brain-web/src/views/admin/ToolGrantPanel.vue#L107>)、[DefaultToolResourcePolicy.java](<../../../haizhuo-brain-platform/src/main/java/com/haizhuo/brain/platform/tool/DefaultToolResourcePolicy.java#L12>)。

### B3. 完整回答与原文校准（P1）

可确认的数据流：

1. Run 成功时，后端将完整正文单独保存到结果表，并为完成事件关联 resultId。
2. 事件写入统一经过 summary，正文长度大于 4,000 时被裁剪。
3. 页面 Presenter 收到 RUN_COMPLETED 后，用事件文本替换此前累积的流式文本。
4. 前端虽然定义了 getRunResult，当前所有页面/Presenter 都没有调用它，也不使用事件 resultId 获取正文。

建议在完成、刷新、补读恢复时，用完整结果接口校准最终回答；需要时增加结果详情/复制/导出。业务结果与用于时间线的短摘要应分别消费。验收应包含超过 4,000 字符的答案、断线补读和刷新。

这是静态链路确认的风险，本轮未运行浏览器复现或测试。

证据：[JdbcRunExecutionStore.java](<../../../haizhuo-brain-infrastructure/src/main/java/com/haizhuo/brain/infrastructure/run/JdbcRunExecutionStore.java#L272>)、[JdbcRunEventAppender.java](<../../../haizhuo-brain-infrastructure/src/main/java/com/haizhuo/brain/infrastructure/run/JdbcRunEventAppender.java#L83>)、[SessionRecoveryController.java](<../../../haizhuo-brain-api/src/main/java/com/haizhuo/brain/api/session/SessionRecoveryController.java#L26>)、[app.ts](<../../../haizhuo-brain-web/src/api/app.ts#L32>)、[runEventPresenter.ts](<../../../haizhuo-brain-web/src/presenters/runEventPresenter.ts#L62>)。

建议独立呈现“引用已完成结果”，在有多个角色时再显示专家选择，继续由后端验证属主、Session、结果可见性和引用数量。

### B5. 历史 Run、工具记录与细节选择（P2）

后端可以按 Session 列出 Run，查询单个 Run、工具记录和事件。页面只自动挑选活动或最近 Run；抽屉跟随当前 run，没有用户选择旧 Run 的入口。

## D 类：不能按“后端已交付，只差前端”统计的项目

- 在线创建/删除数字员工：现有 HTTP 管理只编辑既有员工草稿，没有完整创建生命周期。
- 每轮 COLLABORATIVE/AUTONOMOUS 模式：当前服务明确拒绝；员工 Team profile 的原生接入与此分别判断。
- 可写长期记忆：校验明确拒绝，Harness hooks/tools 当前禁用。
- 任意 USER_SELECTION、多媒体/文档/成果物内容块：类型和 Renderer 注册表存在，当前没有通用渲染业务闭环；工具批准/拒绝是已经接入的特定流程。
- 细粒度目标资源授权：默认平台策略返回允许，尚不是完整资源权限管理。
- 生产 MCP 身份/凭证：模拟接入不等于企业身份接入。
- 真实 IM：统一模拟 Webhook 和模拟发送器不能等同提供方真实协议与送达验收。
- 会议室生产业务：历史 Mock 种子/表已退出，残留执行器不能作为当前生产功能交付依据。
- 完整知识库/RAG：当前知识能力是文件资产和只读加载，完整文档导入、检索索引、检索评测及权限链路不在当前已实现 UI 的证据范围。

这些项目的前端形式应随实际后端范围再定，不应先堆出看似可用的入口。

## 建议实施顺序与验收场景

1. **账号激活 + 完整回答校准**：管理员创建用户后，用户通过页面完成激活并登录；超过 4,000 字符的回答在实时、刷新、断线恢复后保持完整。
2. **员工运行配置与版本查询**：配置表单能回读已有配置、保存冲突不覆盖、校验能定位字段；发布开关继续限制未验收方式，旧 Session 保持冻结版本。
3. **渠道管理与运行核查**：管理员完成账号登记、默认员工/隔离修改、身份绑定与撤销，并在页面看见实际装载状态；真实提供方验证独立列出。
4. **异常 Run 核查**：查询待核查 Run、确认旧执行停止证据、幂等终止，核查完成后会话解除占用；普通用户权限不能调用管理处置。
5. **操作体验补齐**：日常改密、更多用户授权与撤权、单员工结果引用、已发布资产查看、历史运行详情、轻量反馈。
6. **管理可见性**：安全协作投影、投递状态、审计查询、发布版本管理；每项与实际后端查询契约一起完成。

继续复用 AgentScope Java 2.0.3 的 Harness、计划、技能/子 Agent、Team 与 Channel 扩展。补页面应消费平台现有可信身份、Session/Run 和 Delivery 边界，不在前端或新服务中复制智能体循环、队列和协作算法。

## 文档与当前实现的校准

仓库 SPEC-14 的管理页面段描述了运行方式、固定成员/版本、预算等目标，但当前 DefinitionPanel 只有基础字段；完整结果按 resultId 校准也是该文档的目标，当前页面没有调用全文接口。这些项按源码事实列为缺口。

近期协作阶段报告明确保留新运行方式关闭、真实浏览器和外部渠道尚未验收的边界；本轮未重跑其历史测试，不把报告中的测试通过数字视为本次验证结果。
