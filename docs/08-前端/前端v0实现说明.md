# 海卓智慧大脑前端 v0 实现说明

> 状态：已实现基础版本
>
> 范围：Vue 3 + TypeScript + Vite 前端，以及支撑前端真实链路的最小后端查询接口。

## 1. 实现目标

前端 v0 的核心不是复制后端领域模型，而是把已经存在的身份、数字员工、Session、Run 和 RunEvent 链路变成可使用的界面：

```text
登录
  ↓ Cookie + Redis WebSession
数字员工
  ↓ 创建新 Session
会话
  ↓ 一条消息创建一个 Run
Run / Event 轮询
  ↓ Presenter 转换
聊天消息 + 运行详情
```

普通用户看到“数字员工 → 会话 → 消息”；Run、DefinitionVersion 和 Event 只在运行详情中出现。

## 2. 实现模块

| 模块 | 职责 |
| --- | --- |
| `src/api/httpClient.ts` | Cookie、CSRF、401 跳转和统一 HTTP 配置 |
| `src/api/auth.ts` | 登录、当前用户、退出登录 |
| `src/api/app.ts` | 数字员工、Session、Run、RunEvent 类型化请求 |
| `src/stores/auth.ts` | 当前登录用户和管理员菜单状态 |
| `src/stores/app.ts` | 数字员工和最近 Session 展示状态 |
| `src/presenters/runEventPresenter.ts` | 将 Runtime Event 转换为聊天消息 |
| `views/app/SessionView.vue` | 发送消息、轮询 Run/Event、禁用活跃 Run 重复提交 |
| `views/app/SessionView.vue` | Drawer 形式的 Run Inspector |

## 3. 状态边界

后端是业务事实来源。前端只保存当前用户展示信息、页面数据、当前 Run/Event 游标和界面状态。

前端不保存 JWT，也不把 UserId、角色或资源所有权作为可信权限依据。

## 4. Run/Event 处理

一条消息通过当前真实路径创建 Run：

```text
POST /api/v1/sessions/{sessionId}/runs
GET  /api/v1/sessions/runs/{runId}
GET  /api/v1/sessions/runs/{runId}/events?after={sequence}
```

轮询默认间隔约 800ms。`USER_INPUT` 映射为用户气泡，`AGENT_MESSAGE` 和 `MODEL_DELTA` 映射为助手消息，`RUN_STARTED`、`TOOL_CALL` 等运行事件保留在 Inspector 中，不直接污染聊天区。

状态机器以服务端枚举为准。展示层只做文案映射：

```text
QUEUED → 正在等待
RUNNING → 正在处理
WAITING_CONFIRMATION → 等待继续操作 / 补充信息
SUCCEEDED → 已完成
FAILED → 执行失败
CANCELLED → 已取消
```

## 5. 为前端补充的后端查询能力

新增：

```text
GET /api/v1/employees
GET /api/v1/sessions?limit=20
```

前者只返回用户视图字段，不返回模型、能力实现和运行时配置；后者根据已认证用户查询最近 Session，并限制最大返回数量。

## 6. 当前明确限制

- 重新进入历史 Session 时暂不恢复历史消息；页面只展示本次进入后新产生的消息。
- 管理中心当前接入能力目录；用户列表、审计列表等查询 API 尚未在后端已有管理边界中形成，因此没有伪造前端数据。
- Worker 未启用时，Run 会停留在 `QUEUED`，前端仍能展示 `USER_INPUT` 和当前 Run 状态。
- 目前使用 Polling，没有引入 SSE/WebSocket。

## 7. 启动方式

在 `haizhuo-brain-web` 目录执行：

```text
npm install
npm run dev
```

开发服务器默认运行在 `5173`，`/api` 请求代理到后端 `8080`。
