## 3. 对实际工程的核对结果

- 根 POM 目前聚合十个模块：含 `haizhuo-brain-platform`，不含独立 BOM 或 `haizhuo-brain-meeting`。首个业务验证场景已调整为[Mock 会议室预定](../05-业务闭环/会议室预定首个业务闭环详细设计.md)，由发布的 Skill 与受控 Tool 组成；会议整理留待后续。
- `security` 目前只有身份、角色和授权等契约；没有可用的手机号密码登录、账号停用联动、确认消费或完整授权实现。`api` 也没有业务登录、渠道 webhook 与对话入口。
- `platform` 已有数字员工、渠道、Session/Run 等部分对象和端口，但缺少持久化约束、inbox/outbox、worker 和完整运行协调。`runtime-agentscope` 尚未形成真实执行链路。
- 旧初始化文档要求的 Maven Wrapper、Flyway 迁移和 MySQL/Mapper 集成验收不能仅凭旧稿视为已完成；当前仓库未见 Wrapper 或 Flyway 依赖与迁移文件。实施时以现有根 POM 和代码为起点，并重新验证依赖与迁移方案。
- 旧稿中独立 `meeting` 领域模块、租户 SQL、按 Group 授予 Skill、企业 SSO 和外部 Token 作为登录凭证的描述，不进入一期实现任务清单。

## 4. 开发时的核对顺序

1. 先确认专题中是**已确认规则**、**建模建议**还是**待对接事实**；不要将示意字段直接当数据库字段。
2. 对照当前代码和根 POM 判断现有契约、占位实现与目标功能的差距，按[AgentScope 接入验证清单](../06-开发指南/智能体框架接入验证清单.md)验证框架路径。
3. 对外部业务动作，先形成逐系统的默认只读清单、写操作授权与确认规则，再开放工具；没有可信目标范围、可控工具路径或可验证凭证映射时保持拒绝。
