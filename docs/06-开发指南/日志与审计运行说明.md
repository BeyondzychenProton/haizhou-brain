# 日志与审计运行说明

## 目标与边界

平台把“排障日志”和“业务审计”分开保存：日志用于判断服务发生了什么，审计用于追溯谁在什么时间做了关键操作。两者都不得记录密码、Cookie、会话标识、Authorization、模型密钥、请求体或模型原始响应。

## 已启用的记录

| 类别 | 位置 | 可回答的问题 | 安全边界 |
| --- | --- | --- | --- |
| HTTP 请求日志 | 控制台及 `logs/haizhuo-brain.log` | 某次请求是否到达、状态码、耗时 | 仅方法、路径、状态、耗时与 `X-Request-Id`；不记录参数和请求体 |
| 运行日志 | 同上 | Run 是否被 worker 领取、完成或失败 | 仅 Run/Session/版本标识、结果长度和异常类型；不记录用户输入与结果正文 |
| 用户与认证审计 | MySQL 的 `platform_user_audit`、`platform_authentication_audit` | 用户创建、角色变化、认证成功/失败 | 主体与来源按既有实现散列，不保存密码或会话值 |
| Agent 配置审计 | MySQL 的 `agent_definition_management_audit` | 员工定义何时被谁修改/发布 | 不保存敏感凭据 |
| Run 事件 | MySQL 的 `platform_agent_run_event` | Run 状态变化和面向产品的事件流 | 面向业务读取，不能替代基础设施日志 |

## 文件日志与轮转

应用启动后默认写入相对工作目录的 `logs/haizhuo-brain.log`。单个文件达到 50MB 或跨天后轮转，压缩文件保留 30 天，总量最多 2GB。部署环境可以通过环境变量 `LOG_PATH` 指定绝对目录，例如：

```powershell
$env:LOG_PATH = 'D:\haizhuo-logs'
```

生产环境应由日志采集器收集该目录，不建议让业务人员直接下载或传播原始日志。

## 一次问题定位的最小流程

1. 从浏览器响应头或网关记录中取得 `X-Request-Id`。
2. 在 `haizhuo-brain.log` 中按该值定位 HTTP 请求、状态码和耗时。
3. 若问题涉及 Agent 运行，再按 `runId` 查找 `run.worker.*` 日志，并用 Run 查询接口或 `platform_agent_run_event` 对照状态。
4. 若问题涉及账号权限，再查看认证/用户审计表；不要通过日志猜测密码或会话状态。

## 级别建议

- `local`：可保留 `com.haizhuo.brain=DEBUG` 以便开发，但不得增加敏感字段输出。
- `prod`：保持根日志与平台包为 `INFO`，持久层为 `WARN`；异常排查完毕后应恢复该级别。
- 任何新增日志都应记录稳定的业务标识和异常类型，而非对象 `toString()`、HTTP 头、SQL 参数或第三方响应全文。
