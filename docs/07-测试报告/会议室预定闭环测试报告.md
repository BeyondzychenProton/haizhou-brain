## 3. 真实模型端到端验证

### 3.1 成功预定与重启恢复

使用真实 `qwen3.7-max` 请求预定 A-201：2026-10-10 14:00–15:00，6 人。AgentScope 先查询空闲情况，再经受控工具提交预定。

- Run：`a8d59276-2d41-4fb1-8404-491f1d413fb1`
- Run 状态：`SUCCEEDED`
- 业务结果：`BOOKED`
- Mock 预定编号：`BK-3C3D40CDED9D4BD2`
- 预定参数：A-201，6 人，2026-10-10 14:00–15:00（Asia/Shanghai）
- 用 Run 查询接口和 `/mock/api/v1/bookings/{bookingId}` 分别核验，返回同一个编号。
- 停止并重启服务后，Run 和该预定仍可读取，编号一致；Flyway 不重复执行迁移。

### 3.2 请求幂等

- Run：`fb645eef-2525-429a-9a2d-debd679a8e01`。
- 对相同 `clientRequestId` 和相同请求内容再次提交，API 返回同一个 Run ID。
- 同一请求键提交不同正文返回 HTTP `409`。
- 最终只核验到该 Run 对应的一笔预定：`BK-3C26ED0E06494B24`。

### 3.3 冲突和缺少条件

- 真实模型再次申请已占用的 2026-10-10 14:00–15:00 时段，返回业务结果 `UNAVAILABLE`，Run 中没有 booking；查询接口仍将该时段标记为不可用。
- 真实模型收到“帮我预定一间会议室”后返回缺少日期、起止时间和参会人数的提示，业务结果为 `NEEDS_INFO`，没有 booking。
- 对已占用时段直接调用本地 Mock 写接口返回 HTTP `409`；缺少 Run 请求必填的 `message` 返回 HTTP `400`。

## 4. 配置与复现

本机运行配置文件为 `config/application-local.yml` 和 `config/application-meeting-mock.yml`，二者已由 Git 忽略。此项目的应用配置从 YAML 加载，不从环境变量注入。运行脚本需要 JDK 17 和 Maven 3.9 或更高版本；`JAVA_HOME` 仅用于选择 Java 工具链。

先按 [外置运行配置说明](../../config/README.md) 检查本地 YAML，再从项目根目录运行：

```powershell
.\scripts\run-meeting-mock.ps1
```

运行服务后，调用顺序为：

1. `POST /api/v1/sessions`
2. `POST /api/v1/sessions/{sessionId}/runs`，请求体包含唯一 `clientRequestId` 和 `message`
3. 轮询 `GET /api/v1/runs/{runId}` 直到 `SUCCEEDED` 或 `FAILED`
4. 成功时用 `GET /mock/api/v1/bookings/{bookingId}` 核验预定

## 5. 已知边界

- 这是本机开发 Mock，不含前端、手机号密码登录、正式用户管理、多会议室选择或真实会议室系统接入。固定测试身份为 1001；没有认证的 API 只能在 loopback 上使用。
- 数据库账号需有创建本地开发库的权限；首次库创建和 Flyway DDL 属于本地开发初始化。
- Redis 不是业务依赖，也未验证其认证配置。服务健康以 MySQL 和应用状态为准。
- 本机 Maven `settings.xml` 在构建时给出格式告警，但本次测试和打包均成功；这是开发机 Maven 配置告警，不是项目 POM 错误。
- 本轮验证的是单机 Mock 的事务、唯一键和重启读取，不代表真实会议系统的跨服务事务、超时恢复或生产可用性。
