## 2. 本次实现

### 2.1 原生能力复用

仍由 HarnessAgent.streamEvents、AgentEvent、原生 agent_spawn/agent_send 及原生子管理器负责执行。平台只适配来源与业务根事件，没有重写推理、计划、子调度或消息总线。

[NativeSubagentEventContractTest](../../haizhuo-brain-runtime-agentscope/src/test/java/com/haizhuo/brain/runtime/agentscope/harness/NativeSubagentEventContractTest.java) 使用真实父/子 Harness、InMemoryAgentStateStore、临时工作区与原生工具；模型脚本仅确定输入和响应。实际两次子执行、工具返回与历史均有断言。

### 2.2 来源与事件隔离

- 新增 [AgentEventDescriptor](../../haizhuo-brain-runtime-api/src/main/java/com/haizhuo/brain/runtime/api/event/AgentEventDescriptor.java)、AgentExecutionRole 与 AgentInternalEvent。保存原生 ID、时间字符串、类型、source、reply/block/tool-use/session 和白名单关联信息，以及可信 attempt/fence。
- 旧根事件构造器继续可用；平台生成事件可以没有原生描述。未复制任意 metadata，不引入原始工具参数或思考内容。
- [AgentScopeEventTranslator](../../haizhuo-brain-runtime-agentscope/src/main/java/com/haizhuo/brain/runtime/agentscope/event/AgentScopeEventTranslator.java) 只允许 ROOT 驱动根完成/取消/外部等待、主答案与根 Plan；CHILD/UNKNOWN 仅返回选定的 INTERNAL 事件。
- [AgentScopeRuntime](../../haizhuo-brain-runtime-agentscope/src/main/java/com/haizhuo/brain/runtime/agentscope/AgentScopeRuntime.java) 每次订阅用 Flux.using 建立/释放独立 translator。Plan 按 run/reply/tool-use 关联，64 个待结束流、每流 128K 字符上限；已知非 Plan 参数不保留。
- 完成、异常、取消后作用域关闭，迟到事件不再翻译；子结果不清除根 Plan。既有外部工具挂起后抑制根完成的规则保留。

### 2.3 修正测试夹具接线

完整回归暴露 [McpPersistedRunLoopMysqlTest](../../haizhuo-brain-bootstrap/src/test/java/com/haizhuo/brain/bootstrap/mcp/McpPersistedRunLoopMysqlTest.java) 的现有接线遗漏：Harness 使用 JDBC StateStore，Runtime 却通过旧三参数构造器得到 null StateStore；工具恢复请求要求 stateRequired，因而被已有 RUNTIME_STATE_MISSING 检查拒绝。

本轮只把同一个 JdbcAgentStateStore 注入测试 Runtime，保留生产状态检查与全部恢复断言。恢复后工具 SUCCEEDED/READY、Run SUCCEEDED、结果 DELIVERED 与两次模型调用均通过；没有通过放松恢复检查消除失败。

## 3. 原生事件探针结论

| 实际场景 | 观测与约束 |
| --- | --- |
| 模型 spawn/send 参数 timeout_seconds=0 | 可信 CTX_FORCE_SYNC 覆盖；返回完整子结果而非后台 accepted |
| spawn 后 send 跟进 | 同一子实例执行两次；第二次历史含初始任务、第一次结果与跟进消息 |
| 根结果 | 恰一个 AgentResultEvent，source=null；平台只产生一个根完成候选 |
| 本地子事件 | 子文本与生命周期 source=parentSessionId/subagentType；经平台适配不进入根答案 |
| 子最终结果 | 本地 Agent.call() 不另发子 AgentResultEvent；完整结果来自原生调用返回的消息/工具边界 |
| 关联字段 | 原生事件 ID/时间存在；描述保留字段；source 不唯一标识同类型并发实例 |

因此，SPEC-09 必须验证原生调用边界与可信实例/invocation 映射，不能只等子 AgentResultEvent，也不能用 source 猜测实例。远程子路径和 Team 事件另行验证。

最初的确定性脚本只填 ToolUseBlock.input，未提供原生流所需的 content 参数结构；修正脚本后真实工具执行成功。探针原先预期三个 AgentResultEvent，与本地 call 路径不符；经同版本源码和实际历史/返回结果校准为一个根结果，同时保留子执行、跟进历史与完整返回断言。这是协议校准，不是复制框架执行逻辑。
