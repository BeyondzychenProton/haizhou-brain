### 2. `a35955f` — 收尾 Run 实时流的健壮性遗留项

4 个文件，68 增 / 13 删。

- 补读加有界重试 `Retry.backoff(2, 200ms).maxBackoff(2s)`：数据库抖动不再终止整条 SSE，重试耗尽才把错误交给浏览器退避重连。
- 修复真实缺陷：`Flux.interval + concatMap` 在上一次补读未结束时抛 `OverflowException: Could not emit tick ... due to lack of requests`，直接终止整条流（慢数据库比断线更致命）。已加 `.onBackpressureDrop()`。
- 新增 `eventsOfOwnedRun`：补读复用订阅时已校验的归属结论，去掉每次轮询的重复 `getRun`（仓储仍按 owner 过滤，可见性不放松）。
- 删除不再调用的 7 参 NOOP 构造。
- 新增 2 个回归用例：瞬时故障恢复、持续故障按错误终止且只重试 3 次。

## 关键设计决策

| 决策 | 理由 |
| --- | --- |
| SSE `id` 只绑持久游标（Run 绑 `sequenceNo`，会话绑 `sessionCursor`） | 瞬时 `streamOffset` 不可重放，进 `id` 会让浏览器在重连时请求一个后端无法补读的位置 |
| 瞬时事件带 `attemptId`，offset 在单次尝试内递增 | 同一 Run 重跑时 offset 会重置，否则重连后 `eventId` 冲突、delta 被前端去重丢弃 |
| 实时投递异常一律吞掉 | 实时链路是可降级展示，不能反向改写业务终态；`settle()` 事务语义未动 |
| 会话游标用投影表而非改写 `platform_agent_run_event` | 不影响既有 Run 语义与迁移历史；投影可从持久事件重建 |
| 游标分配锁 session 行 + `COALESCE(MAX(session_cursor),0)+1` | 复用既有 `appendEvent` 的串行化写法，保证会话内单调 |
| 投影写入必须覆盖 `JdbcSessionRunStore` 与 `JdbcRunExecutionStore` 两处 | 漏任何一处，会话游标就会出现空洞 |
| 历史补入用 `ROW_NUMBER() OVER (PARTITION BY session_id ORDER BY created_at, run_id, sequence_no)` | 确定性排序；H2 不支持 `UPDATE...JOIN`，故用 `INSERT...SELECT` |
| 归属校验在订阅前完成，且每次 SSE 订阅都校验 | 未引入 `X-User-ID`；GET SSE 不触发 CSRF |
