本文整理[初版概要设计](../01-平台总览/平台概要设计.md)中的运行规则。行为原则以概要设计为维护入口；本文不定义具体接口、数据库、线程模型或框架 API，也不代表功能已实现。

多渠道、身份、授权与发布细则见[当前设计总览](../01-平台总览/设计文档总览.md)。现有 `platform` 仅有契约骨架，以下链路是目标行为。

## 1. 主请求链路

```text
Web API 提交需求（如含资料，先由上传接口保存，工作请求只引用受控资源）
  → 登录态、账号状态、输入与资源归属校验
  → 请求去重、Session 活跃执行校验、建立 Run
  → 内部执行器调度（并发不足时等待资源）
  → 开始执行时重检账号并固定已发布定义、能力修订与有效上下文
  → AgentScope Java 运行统一助手
      → 关联上下文、理解需求，必要时检索原文或澄清
      → 按需规划；只规划请求不执行所规划的工作
      → 按需加载 Skill、调用工具
      → 必要时顺序委派专业 Agent，接收结果
      → 根据真实执行结果自检并统一交付，说明缺口
  → 保存结果、按需保存产物、工作事件与终态，结束 Run

执行过程 → 记录状态与事件 → 网页展示进度与控制反馈
网页控制 → 校验目标 Run / 等待点 → 运行时落实 → 返回实际反馈
```

接收需求与持续执行分开，网页断线不自动取消 Run。Web 从已保存的工作事件通过 SSE 或查询获取进度、结果并在重连时补齐；具体事件字段与接口形式在详细设计时确定。异步消息渠道另按[多渠道设计](数字员工多渠道接入与消息流转设计.md)保存出站意图并投递。

主 Agent 的行为边界见[概要设计第 4 节](../01-平台总览/平台概要设计.md#4-agent-与-skills-的组织)。上述步骤是职责示意，不要求固定模型调用顺序；计划不默认阻塞执行，用户验收也不是每次 Run 结束的必经步骤。能力发现不扩充授权，运行结束不等于业务目标全部达成。

| 阶段 | 主要职责 | 控制边界 |
| --- | --- | --- |
| 接收 | 识别已认证用户、Session、输入和附件引用 | 校验会话与资源归属；客户端参数不能替代认证和授权 |
| 建立执行 | 去重、判断是否可创建 Run、保存请求与状态 | 同一 Session 只有一个活跃 Run；重复提交不创建重复执行 |
| 调度 | 在并发上限内安排已接收 Run | 资源等待不等于同一 Session 新任务排队；活动 Run 中普通新任务一期忙时拒绝并留痕 |
| 创建 Run | 解析并冻结 Agent Definition Version、Definition Workspace Layer、模型可见能力范围及相关上下文 | 与 Run 创建事务一致；排队等待不改变版本 |
| 准备执行 | 读取 Run 已冻结配置，建立调用级状态与运行目录绑定 | 复核账号/渠道/紧急停用，不重新选择最新发布配置 |
| 执行 | 统一助手组织 Skills、工具及专业 Agent | 工具执行时落实权限、超时、预算和取消检查 |
| 反馈 | 保存状态、关键动作与控制反馈 | 已收到输入不等于已应用；已收到取消不等于已停止 |
| 收尾 | 保存已有结果、产物及终态原因 | 部分失败保留成果；避免重复外部操作；旧执行未停止时不启动抢占执行 |

## 2. 执行中的交互路径

输入意图由网页显式操作表达，完整规则见概要设计第 6.2 节。

- 补充：关联当前 Run，接收后在安全执行边界应用；若原 Run 已结束，保留输入并提示重新发送。
- 取消：请求停止，待实际执行停止后反馈；已完成的外部动作不自动回滚。
- 抢占：保存替代请求，取消原 Run，确认停止后开始新 Run。
- 回应等待：关联原 Run 及具体问题或审批点，校验后继续原执行。

前端显示整体状态、实际关键动作和控制反馈，不展示模型内部推理。审批使用明确入口，自由文本不自动表示允许。

### 2.1 执行事件到用户界面

展示原则集中维护于[概要设计第 6.4 节](../01-平台总览/平台概要设计.md#64-网页执行过程展示已确认)。后端提供真实动作、对象、状态及结果；前端生成常规文案、聚合过程并更新原展示项；主 Agent 提供必要的工作说明，不为每次调用重复输出聊天文字。

- 正文、过程组、成果卡片和用户交互分别呈现；重要结果、待回答或授权事项及影响交付的异常不被折叠隐藏。
- 展示真实阶段和可准确计量的局部进度，不估算 Agent 整体百分比。
- 新事件不打断历史阅读或强制收起详情；重连恢复已有内容、真实状态及仍有效的操作入口，不重复展示或执行。
- 临时失败与重试更新原过程项，已恢复失败保留在详情；影响交付的问题明确提示，技术诊断内容不直接暴露。

以上不决定具体事件字段、传输协议或 UI 组件；界面聚合不替代服务端状态、权限和等待点校验。

## 3. 异常与限制

| 情况 | 已确认原则 |
| --- | --- |
| 网页断线、刷新 | 服务端继续执行，重连恢复状态和已有内容 |
| 提交响应丢失 | 查询原请求接收情况，避免直接重建 Run |
| 重复控制请求 | 防止取消、补充、抢占、回答和审批被重复处理 |
| 临时失败 | 对可安全重试的具体步骤有限重试，不默认重跑整个 Run |
| 外部动作结果不确定 | 核查结果；无法核实时明确反馈，不当作未执行 |
| 服务重启 | 判断可恢复范围；无法恢复时展示执行中断 |
| 达到执行限制 | 停止继续发起操作，保留结果并说明原因；确认在途操作的实际状态 |
| 等待用户 | 单独计时，不长期占用执行线程；过期策略待详细设计 |

## 4. 工程职责承接

以下是目标职责，模块依赖和数据归属见[整体工程架构](../01-平台总览/平台整体工程架构.md)，具体类与接口仍待详细设计。`platform` 已加入工程，业务流程尚未实现。

| 工程位置 | 职责 |
| --- | --- |
| haizhuo-brain-api | 登录、Web 与 webhook 协议入口；接收需求和控制操作，提供状态查询、结果获取及事件订阅 |
| haizhuo-brain-platform | 内部按员工与能力配置、渠道接入、资源管理、会话管理、执行协调分区；管理 Session / Run、去重、调度、有效配置、出站意图、收尾和恢复 |
| haizhuo-brain-runtime-api | 定义执行、事件与交互控制的运行契约，隔离平台与具体框架 |
| haizhuo-brain-runtime-agentscope | 装配 AgentScope Java Agent，执行模型和工具循环，适配事件及控制能力 |
| haizhuo-brain-security | 平台账号、密码与登录态、授权判断、操作确认及权限撤销规则 |
| haizhuo-brain-infrastructure | 状态持久化、文件和产物存储、外部服务适配 |
| haizhuo-brain-observability | 使用 Langfuse 承接追踪、用量和异常观测；上报故障与主执行隔离，不代替平台工作记录 |
| 会议室预定场景 | 先通过会议室 Skill、受控查询/写入 Tool 与 Mock 接口验证首个完整链路；旧 `meeting` 模块已移出根构建，纪要整理留待后续 |

模型决定提出哪些操作，平台与工具执行层判断是否允许并落实实际操作。约束不能仅依赖 Prompt。平台和 AgentScope 的重试、状态保存及取消职责需要明确，避免重复管理或控制遗漏。

已确认由平台统一工具入口协调授权和调用，具体能力执行实际操作；无权限直接拒绝，确认不能突破权限。Run 可包含多个框架调用，调用返回不等于 Run 结束。等待时的安全收尾、释放执行名额、状态保存失败及控制分工见[整体工程架构第 8 节](../01-平台总览/平台整体工程架构.md#8-交互控制与执行资源已确认设计实现待验证)，具体实现仍需按锁定版本验证。

## 5. 详细设计前的验证顺序

1. 核查项目锁定的 AgentScope Java 对补充输入、取消传播、等待继续和进程恢复的支持，区分原生能力、平台补充和限制。
2. 验证模型与工具超时、执行预算、专业 Agent 消耗汇总，以及等待时释放执行资源的方式。
3. 根据验证结果确定 Run 状态转换及运行时控制契约，覆盖取消与完成竞争、补充晚到和重复回应。
4. 细化请求标识、持久化边界、执行调度、事件推送、重连与工具重试策略。
5. 先按[会议室预定详细设计](../05-业务闭环/会议室预定首个业务闭环详细设计.md)验证 API 提交、AgentScope 工具调用、Mock 预定、授权、幂等、失败与结果查询；随后用会议资料处理等场景验证产物、补充、等待、取消、抢占和界面反馈的完整链路。

当前仍不承诺无条件恢复任意执行步骤，也不承诺通过请求去重即可保证外部副作用恰好执行一次。
